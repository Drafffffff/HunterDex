## 性能口径

重构前本机搜索诊断：中文查询中位约 35 ms，空查询名称排序最高约 122 ms；均不含视图创建。

0.3 发布构建对十组查询的索引搜索实测：中位约 15 ms，最大约 17 ms。以上为后台查询耗时，不含 120 ms 防抖、主线程提交或绘制，不应当成完整输入响应时间。原先卡顿也涉及全量 SwiftUI 行的构建，现由 NSOutlineView 复用行。

## 窗口操作检查

- 启动显示当前武器类型，根节点默认展开，实际列表包含攻击、斩味、属性、会心、孔位。
- 原生搜索框输入“铁矿石”返回 1 条；快速替换为无结果词再换回中文，随后切换防具，窗口正常响应。
- 防具展示技能点、孔位、初始／满强化、五属性耐性、同系列链接与比较入口。
- 实际鼠标点击验证比较：皮制头饰作为基准，选锁甲头盔，显示初始／满强化防御 +1、孔位 +2、反复无常 −2、雷耐性 +1。派生详情按钮跳转也已验证。
- 自动化按无障碍 ID 点击大表格行时超时；进程采样显示主要在处理 AppKit 无障碍属性读取、构建行视图。改用截图坐标点击后立即正常完成。此问题仍限制大列表的无障碍自动化，不把它宣称为全面解决。拼音组词端到端尚未验证。
- 截图发现武器切换防具后旧 outline 列未移除，已改为原位重配已有列并只增减尾部列，避免 NSOutlineView 保留 outline 列造成重复；同时缩减防具名称列宽。最终窗口截图确认只有一列名称，防御、孔位和五属性耐性均完整可见。

## 详情效率与整树控制跟进

- 武器：性能 → 上一级／本次费用 → 制作素材 → 后续派生；路线累计默认折叠，已有起点时自动展开。
- 防具：技能／孔位 → 比较差异 → 防御／耐性 → 素材；同系列默认折叠；比较只列有变化的属性。收藏中的装备也使用专用详情。
- 素材：狩猎／采集／任务来源优先，反向用途及类别归属靠后。只有用途的条目直接显示用途。
- 任务：标题、主要目标、限制时间留在首屏，地图／副任务在前，报酬按原有栏位展示。
- 怪物：插画缩至辅助尺寸；五属性弱点横排，报酬与出现任务紧随。来源／报酬长列表可按下位、上位、G 位过滤。
- 通用详情提供固定栏目导航，每个长列表先显示 6 条，可展开全部；原文、售卖价格、契约金等移至补充资料，不删数据。
- 按用户纠正，树控制仅作用于当前节点及其全部后续派生：底部为“展开当前派生／收起当前派生”，节点箭头递归展开／收起该节点的子树；其他独立武器与旁支保持原状。跳转隐藏目标时只展开祖先路径，类型间保存各分支状态。
- 回归自检增加当前子树范围、独立分支不受影响、收起状态跨类型恢复、主动跳转显示目标、素材详情栏目顺序。
- 窗口验证已确认先前展开交互、任务目标首屏、任务报酬栏目跳转和怪物紧凑弱点展示。

分支作用域修正的回归检查：对照 SQLite 递归查询验证 65793 的全部后代集合；检查另一独立根保持展开；对子节点 65794 收起时保留祖先及不相关根；跨类型返回仍保留局部收起状态。
